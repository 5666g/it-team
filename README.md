## 💡 Архитектурные особенности проекта

1. **Полная независимость задач:**
   Каждому студенту выделен отдельный HTML-файл внутри каталога `pages/`. Разработчики не редактируют один и тот же файл одновременно, что исключает блокирующие конфликты слияния и позволяет сосредоточиться на механике Pull Request.
2. **Гарантированная целостность при неполной посещаемости:**
   Все 8 страниц изначально созданы и содержат аккуратные заглушки («Раздел находится в разработке»). Если на занятии присутствуют только 3–5 студентов, сайт сохраняет 100% работоспособность, ссылки не приводят к ошибкам 404, а незаполненные разделы выглядят гармонично.
3. **Чистый стек без накладных расходов:**
   Не требуется установка Node.js, npm, Webpack, Vite или расширений. Достаточно любого веб-браузера и текстового редактора (например, Visual Studio Code).
4. **Единый дизайн:**
   Все страницы подключают общий файл `style.css` (из корня — напрямую, из папки `pages/` — через относительный путь `../style.css`).

## 🚀 Порядок участия для студентов

1. Сделайте **Fork** оригинального репозитория преподавателя в свой профиль GitHub.
2. Склонируйте свой форк на локальный компьютер: `git clone https://github.com/ВАШ_ЛОГИН/it-team.git`.
3. Добавьте оригинальный репозиторий как `upstream`:  
   `git remote add upstream https://github.com/rillside/it-team.git`.
4. Создайте отдельную ветку под вашу задачу: `git checkout -b feature/<имя-ветки>`.
5. Отредактируйте назначенный HTML-файл по образцу из `pages/template.html`.
6. Проверьте результат локально в браузере.
7. Зафиксируйте изменения (`git add`, `git commit`) и отправьте ветку в свой форк (`git push -u origin feature/<имя-ветки>`).
8. Откройте **Pull Request** в оригинальный репозиторий преподавателя и дождитесь результатов код-ревью!
